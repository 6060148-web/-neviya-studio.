# סטודיו נביעה — תבנית WordPress

תבנית WordPress מלאה לאתר פורטפוליו של **סטודיו נביעה — עיצוב ושיווק גרפי ודיגיטלי**.
האתר בנוי כסיפור גלילה רציף (scroll story) שמתחיל כאיור עיפרון על נייר, ועובר בהדרגה
לעולם צבעוני ככל שגוללים — כשהצבע "נובע" לתוך הקווים באמצעות SVG masks, לא באמצעות
opacity פשוט. כל התוכן (פרויקטים, קטגוריות, פרטי קשר) מנוהל מתוך וורדפרס, ללא צורך
לגעת בקוד, עם תמיכה מלאה ב-Elementor.

התבנית פותחה ונבדקה בסביבת פיתוח מבודדת ללא גישה להתקנת WordPress/Elementor אמיתית
(ראו סעיף "איך זה נבדק" למטה) — כל קובץ עבר `php -l`, ובנוסף נבנה "harness" שמדמה את
ליבת ה-API של וורדפרס ומריץ בפועל את כל פונקציות ה-render, ה-Widgets של Elementor,
תבניות ה-PHP וה-JS, ותפס ותוקן שני באגים אמיתיים (ראו למטה) לפני המסירה.

כל אתר נביעה חי בתוך תיקיית תבנית אחת (`wp-content/themes/neviya-studio`). זהו
**Classic Theme** רגיל (לא block theme), כדי לשמור על שליטה מדויקת בסצנת הגלילה
ובמבנה ה-HTML/CSS/SVG — אך הוא עדיין לגמרי תואם-Elementor.

## התקנה

> ההוראות כאן הן להתקנה **מהמחשב**. להתקנה מהטלפון — [עברו לסעיף הבא](#התקנה-מהטלפון).

1. העתיקו את התיקייה `wp-content/themes/neviya-studio` לתוך `wp-content/themes/` באתר
   WordPress קיים (גרסה 6.0 ומעלה, PHP 7.4 ומעלה — נבדק גם מול PHP 8.4).
2. בלוח הבקרה: **מראה ← ערכות עיצוב** → הפעילו את **Neviya Studio**.
   הפעלה ראשונה יוצרת אוטומטית את 5 קטגוריות הפרויקטים ומרעננת את חוקי ה-permalinks.
3. עברו ל-**הגדרות ← קישורים קבועים** ולחצו "שמור שינויים" פעם אחת (מוודא שכתובות
   הפרויקטים `/projects/...` יעבדו).
4. עמוד הבית פועל אוטומטית ברגע ההפעלה — אין צורך בהגדרה נוספת (`front-page.php`
   מרכיב את כל 5 הפרקים). אם תרצו לערוך את הסיפור מתוך Elementor:
   א. צרו עמוד חדש, קראו לו למשל "בית".
   ב. בעמוד, תחת **תבנית עמוד**, בחרו **"מסע גלילה – נביעה"**.
   ג. פתחו את העמוד ב-Elementor וגררו את 5 ה-Widgets של נביעה (ראו סעיף הבא).
   ד. תחת **הגדרות ← קריאה**, קבעו את העמוד הזה כ"עמוד סטטי" בתור עמוד הבית.
5. (רשות) תחת **מראה ← Customize ← פרטי קשר – נביעה**, מלאו אימייל, טלפון וקישורים
   לרשתות חברתיות.
6. פרסמו פרויקט ראשון (**פרויקטים ← הוסף פרויקט**), או לחצו על
   **פרויקטים ← תוכן לדוגמה** ליצירת 6 פרויקטי דוגמה מוכנים (ראו סעיף ייעודי למטה).

## התקנה מהטלפון

אפשר להתקין ולנהל את האתר גם בלי מחשב, רק מהטלפון (אייפון או אנדרואיד).
וורדפרס מקבלת תבנית רק כקובץ **ZIP**, לכן הכנו מראש קובץ מוכן: **`dist/neviya-studio.zip`**.

### שלב 1 — הורדת קובץ ה-ZIP לטלפון

1. פתחו בדפדפן של הטלפון את הריפו בגיטהאב ועברו לתיקייה `dist`.
2. לחצו על `neviya-studio.zip` ואז על **Download** (או על אייקון ההורדה).
   - **אנדרואיד (Chrome):** הקובץ נשמר בתיקיית **הורדות**.
   - **אייפון (Safari):** אשרו "הורדה"; הקובץ נשמר באפליקציית **קבצים ← הורדות**.
3. אל תפתחו/תחלצו את ה-ZIP בטלפון — וורדפרס צריכה אותו כקובץ אחד סגור.

### שלב 2 — העלאה לאתר דרך הדפדפן בטלפון

1. התחברו ללוח הבקרה של האתר: `כתובת-האתר/wp-admin` (פתחו מ-Chrome/Safari).
   אם הדף נראה קטן — בחרו בתפריט הדפדפן **"אתר למחשב" / "Request Desktop Site"**.
2. תפריט ← **מראה ← ערכות עיצוב ← הוספה ← העלאת ערכת נושא**.
3. לחצו **בחירת קובץ**, בחרו את `neviya-studio.zip` מהורדות/קבצים, ואז **התקן עכשיו**.
4. לחצו **הפעל**. ההפעלה יוצרת אוטומטית את 5 הקטגוריות.
5. **הגדרות ← קישורים קבועים** ← **שמור שינויים** פעם אחת.
6. (רשות) **פרויקטים ← תוכן לדוגמה** ליצירת 6 פרויקטים מוכנים.

> אם ההעלאה נכשלת בגלל גודל: הקובץ כ-110KB בלבד, אז בדרך כלל הסיבה היא חסימת
> העלאות אצל חברת האחסון — פנו לתמיכה שלה או התקינו דרך מנהל הקבצים (אפשרות ב׳).

### אפשרות ב׳ — דרך מנהל הקבצים של האחסון (cPanel וכד׳)

1. היכנסו מהדפדפן בטלפון לחשבון האחסון ← **מנהל קבצים (File Manager)**.
2. עברו ל-`public_html/wp-content/themes/`.
3. **Upload** ← בחרו את `neviya-studio.zip` ← לחצו על הקובץ ובחרו **Extract / חילוץ**.
4. חזרו ללוח הבקרה של וורדפרס ← **מראה ← ערכות עיצוב** והפעילו את **Neviya Studio**.

### ניהול שוטף מהטלפון

- **אפליקציית WordPress** (אנדרואיד/iOS): מאפשרת הוספת פרויקטים, העלאת תמונות
  ופרסום. את התקנת התבנית עצמה, ה-Customizer ו"תוכן לדוגמה" עדיף לעשות דרך הדפדפן
  (שלבים למעלה), כי הם לא זמינים באפליקציה.
- **קיצור למסך הבית** (לגישה מהירה ללוח הבקרה): בכרום — תפריט ⋮ ← **הוסף למסך
  הבית**; בספארי — כפתור שיתוף ← **הוספה למסך הבית**.

## תלויות ותוספים

| תוסף / ספרייה | חובה? | הערות |
|---|---|---|
| WordPress 6.0+ | חובה | |
| PHP 7.4+ | חובה | נבדק גם מול PHP 8.4 |
| GD extension | מומלץ | רק לצורך "תוכן לדוגמה" (יצירת תמונות Cover גנריות) |
| Elementor (חינמי) | רשות | נדרש רק אם רוצים לערוך את הפרקים ויזואלית. **האתר עובד באופן מלא גם בלעדיו** — כל 5 הפרקים מוצגים אוטומטית דרך `front-page.php`, ויש גם shortcodes (`[neviya_hero]`, `[neviya_about]`, `[neviya_domains]`, `[neviya_projects]`, `[neviya_contact]`) לשילוב בכל עמוד ללא Elementor. |
| Elementor Pro / ACF | **לא נדרש** | כל שדות הפרויקט ממומשים כ-native post meta (ללא תלות בתוסף חיצוני). אם יש ACF מותקן ופעיל, `neviya_get_project_meta()` יודעת לעבור אליו (דגל `neviya_use_acf` באופציות) — אך זו אופציה מתקדמת, לא דרישה. |
| GSAP + ScrollTrigger | כלול בתבנית | קבצים מקומיים תחת `assets/js/vendor/`, **לא** נטענים מ-CDN. גרסה 3.15, חינמית במלואה (מ-2025 GSAP וכל התוספים שלה חינמיים לחלוטין, כולל שימוש מסחרי). |
| Google Fonts (Frank Ruhl Libre + Heebo) | כלול | נטען דרך `<link>` עם `preconnect`; יש `font-family` fallback מלא (`serif` / `sans-serif`) כך שהאתר לא "קורס" אם הגישה ל-Google Fonts חסומה. |

**התבנית לא טוענת שום ספריית JS נוספת** מעבר ל-GSAP/ScrollTrigger, ורק בעמודים
שבאמת זקוקים לאנימציית הגלילה (`is_front_page()`, תבנית "מסע גלילה", ועמוד פרויקט
בודד) — ראו `inc/enqueue.php::neviya_needs_story_engine()`.

## חיבור ל-Elementor

לאחר הפעלת תוסף Elementor, בפאנל הרכיבים (בעת עריכת עמוד) תופיע קטגוריה חדשה בשם
**"סטודיו נביעה"** עם 5 Widgets — אחד לכל פרק בסיפור:

| Widget | מה הוא שולט |
|---|---|
| נביעה — הירו (פתיחה) | שורת פתיחה, כותרת ראשית, טקסט משני, טקסט סימון גלילה |
| נביעה — על הסטודיו | כותרת + רשימת משפטים (repeater, ניתן להוסיף/להסיר/לסדר מחדש) |
| נביעה — תחומי יצירה | כותרת בלבד — התחומים עצמם מנוהלים תחת **פרויקטים ← תחומי יצירה** |
| נביעה — פרויקטים נבחרים | כותרת, סינון לפי תחום (dropdown דינמי מהטקסונומיה), הצגת "נבחרים בלבד" כן/לא, כמות |
| נביעה — צור קשר | כותרת, טקסט הזמנה, override לאימייל/טלפון (ברירת מחדל: מה שהוגדר ב-Customizer) |

כל Widget הוא "דק" בכוונה: הוא רק ממפה את השדות שלו ומעביר אותם לאותה פונקציית
`neviya_render_*_section()` שמשמשת גם את `front-page.php` וגם את ה-shortcodes — כך
שהעריכה ב-Elementor, עמוד הבית האוטומטי וה-shortcodes תמיד נראים אותו דבר, ואין
כפילות קוד לתחזק.

**עמוד פרויקט בודד**: התבנית `single-neviya_project.php` היא תבנית PHP רגילה (לא
Elementor Theme Builder — זה דורש Elementor Pro). היא מציגה את כל השדות (Cover,
גלריה, וידאו, שירותים, לקוח, שנה, קישור חיצוני) בעימוד סמנטי ונגיש, וניתנת לעריכת
עיצוב (צבעים/רווחים) ישירות ב-`assets/css/projects.css`. אם יש לכם Elementor Pro
ותרצו Theme Builder Single Template במקומה — אפשר, אך זה לא נדרש לתפקוד מלא.

## איך מוסיפים פרויקט חדש

1. **פרויקטים ← הוסף פרויקט**.
2. כותרת = שם הפרויקט. תוכן העורך = התיאור המלא (מוצג בעמוד הפרויקט הבודד).
   תקציר (Excerpt, בפאנל הצד) = תיאור קצר לכרטיס.
3. תמונה ראשית (Featured Image) = תמונת ה-Cover.
4. תחת **תחומי יצירה** בפאנל הצד — בחרו קטגוריה אחת או יותר (מתוך 5 ברירות המחדל,
   או קטגוריה חדשה שתוסיפו).
5. בתיבת **"פרטי הפרויקט"** (מתחת לעורך):
   - **לקוח / שנה / שירותים** (שורה אחת לכל שירות) — טקסט חופשי.
   - **צבע מוביל** — color picker; קובע את צבע הפילים/הכפתורים של אותו פרויקט.
   - **כתובת וידאו** — קישור YouTube, Vimeo, או קובץ `.mp4/.webm/.ogg` ישיר.
   - **קישור לאתר/פרויקט חיצוני** + **טקסט לכפתור**.
   - **פרויקט נבחר** — סמנו כדי שהפרויקט יופיע בעמוד הבית (`featured=true`).
   - **סגנון חשיפה בגלילה** — קובע איזו אנימציה ילווה את הפרויקט הזה בעמוד הבית:
     `מסכת עיפרון` (ברירת מחדל), `שכבת נייר מחליקה`, `תצוגת וידאו`, `מסגרת דפדפן`,
     `מעבר מסקיצה לסמל`. את הקצב המשתנה בין פרויקטים קובעים דרך השדה הזה, לא דרך
     קוד אקראי לכל פרויקט.
   - **תמונת סקיצה** + **תמונה צבעונית** — אופציונלי; אם שתיהן קיימות, "מסכת עיפרון"
     ו"מעבר מסקיצה לסמל" ישתמשו בהן. אם חסרות — התבנית נופלת אוטומטית לתמונת ה-Cover
     הרגילה (ללא placeholder שבור).
   - **גלריית תמונות** — לעמוד הפרויקט הבודד.
6. **סדר הצגה** נקבע דרך שדה ה-**Order** הרגיל של וורדפרס (Page Attributes, בפאנל
   הצד) — מספר קטן יותר = מוצג קודם.
7. פרסמו. הפרויקט יופיע אוטומטית בעמוד הבית (אם מסומן "נבחר"), בעמוד
   `/projects/` (כל הפרויקטים), ובעמוד הקטגוריה שלו.

כל השדות זמינים גם כ-**Elementor Dynamic Tags** (Post Meta) לפי מפתח השדה
(לדוגמה `_neviya_client`), למי שרוצה להשתמש בהם בתוך Widgets מותאמים אישית של
Elementor עצמו.

## החלטות אנימציה וביצועים

- **GSAP + ScrollTrigger, לא scroll hijacking**: כל אנימציה היא scroll-*linked*
  (scrub, או "once" בכניסה ל-viewport) — הגלילה עצמה נשארת טבעית לגמרי, לעולם לא
  ננעלת, מואטת מלאכותית, או "מקפיצה" בין פרקים.
- **Sticky, לא pin**: פרק ה-Hero משתמש ב-`position: sticky` (לא ב-ScrollTrigger
  `pin`) — פשוט יותר, לא מתנגש עם Elementor/תוספי גלילה אחרים, ולא דורש refresh
  ידני של חישובי גובה.
- **CSS הוא ברירת המחדל, JS הוא שיפור**: כל אפקט (מסכת צבע, קווים מצוירים, כרטיסי
  פרויקט) יש לו מצב "revealed" מלא ב-CSS. אם JS נכשל בטעינה, לא רואים אלמנטים
  תקועים חצי-מוסתרים — רואים את הגרסה הסופית המלאה.
- **`prefers-reduced-motion`**: `main.js` מזהה את ההעדפה ומוסיף class
  `neviya-reduced-motion` ל-`<html>`; כל קובצי ה-CSS של הסצנות מכבדים אותו class
  ומציגים את המצב הסופי מייד, ללא אנימציה. `scroll-story.js` גם מדלג לגמרי על
  יצירת ה-ScrollTrigger scrub עבור ה-Hero במקרה הזה.
- **טעינה מותנית**: GSAP/ScrollTrigger/`scroll-story.js` נטענים רק בעמוד הבית,
  בתבנית "מסע גלילה" ובעמוד פרויקט בודד (`inc/enqueue.php`) — לא בכל אתר.
  Elementor Editor מקבל אותם אוטומטית גם כשה-widgets שלנו נמצאים בעמוד אחר, דרך
  filter (`neviya_needs_story_engine`).
- **וידאו**: כל סרטון מוצג כ"Preview שקט" (Poster + כפתור הפעלה) — ה-iframe/video
  האמיתי נוצר רק בלחיצה (facade pattern), כדי לא לטעון סקריפטים כבדים של יוטיוב/וימאו
  מראש. `main.js` גם משהה כל `<video>` שיוצא מה-viewport (`IntersectionObserver`).
- **תמונות**: כל `<img>` עובר דרך `neviya_the_image()` שמוסיפה `loading="lazy"`,
  `decoding="async"`, ו-alt text (טקסט חלופי של המדיה, עם fallback לשם הפרויקט) —
  ומונעת layout shift כי גדלי התמונה (`add_image_size`) קבועים מראש.
- **סקריפטים**: `main.js`, GSAP וכו' נטענים עם `defer` (לא render-blocking).

## נגישות ו-SEO

- HTML סמנטי מלא (`<header>`, `<main>`, `<footer>`, `<nav>`, כותרות בהיררכיה נכונה

  ראו סעיף הבדיקות).

  honeypot + sanitize מלא בצד השרת.

  פרויקט (כולל `image`, `genre` לפי הקטגוריות, `dateCreated`).
- כל התוכן החשוב (טקסטים, קטגוריות, קישורים) מגיע דרך `<a href>` רגיל ו-server-side

  ו-`single-neviya_project.php` הם server-rendered מלאים).

## איך זה נבדק

הסביבה שבה נבנתה התבנית הזו **אין בה WordPress/Elementor אמיתיים** (אין גישת רשת
ל-wordpress.org מתוך ה-sandbox). כדי עדיין לוודא היעדר שגיאות PHP/JS ולוודא
שהאינטראקציות עובדות בפועל, נבנה תהליך בדיקה תלת-שכבתי:

1. **`php -l`** על כל קובץ PHP בתבנית — איתור שגיאות תחביר.
2. **`node --check`** על כל קובץ JS — איתור שגיאות תחביר.
3. **"WordPress core stub harness"** — קובץ PHP שמדמה כ-150 פונקציות ליבה של
   וורדפרס (`add_action`, `get_post_meta`, `WP_Query`, `wp_send_json_*` וכו') וגם
   מחלקות Elementor (`Widget_Base`, `Repeater`, `Controls_Manager`). מריצים דרכו
   בפועל את `functions.php`, את חמשת ה-render functions, את כל 5 סגנונות "חשיפת
   פרויקט", את ה-meta box, את handler הטופס (הגשה תקינה + honeypot), את JSON-LD,
   את כל 8 קבצי ה-template, את מחולל התוכן לדוגמה, ואת חמשת ה-Elementor Widgets —
   ותופס כל Fatal Error / Warning אמיתי.
4. **Playwright + Chromium** (מותקן מראש בסביבה) — הרצת התבנית בפועל מול שרת PHP
   מקומי, וצילום מסך אמיתי ב-4 הרוחבים הנדרשים (360 / 768 / 1024 / 1440), כולל
   גלילה בפועל לכל פרק כדי לוודא שהאנימציות רצות.

**שני באגים אמיתיים נתפסו ותוקנו** דרך שלב 4 (לא היו נתפסים ע"י lint בלבד):

- **עומס גלילה אופקי סמוי**: שדה ה-honeypot בטופס יצירת הקשר היה ממוקם עם
  `left: -9999px`, מה שניפח את `document.documentElement.scrollWidth` ל-11,439px
  (למרות ש-`overflow-x: clip` על ה-`<body>` הסתיר את זה חזותית) — ותיקון: מעבר
  לטכניקת ה-clip הבטוחה (`clip-path: inset(50%)`), זהה לזו שכבר שימשה את
  `.screen-reader-text`.
- **מסכת הצבע ב-Hero לא נחשפה בפועל**: כלל CSS שקבע `r: 0` על מעגלי החשיפה התנגש
  עם אנימציית ה-`attr:{r:...}` של GSAP — ב-CSS, geometry properties (כמו `r` על
  `<circle>`) תמיד גוברים על presentation attributes, כך שהערך שנקבע ע"י GSAP
  (`setAttribute('r', ...)`) התעדכן בפועל ב-DOM אך מעולם לא צויר על המסך. תוקן
  ע"י הסרת כלל ה-CSS המיותר (ברירת המחדל `r="0"` כבר מוגדרת ישירות ב-markup של
  ה-SVG עצמו).

בנוסף, ביקורת ויזואלית על צילומי המסך העלתה שכיוון החץ בכפתורי הקריאה-לפעולה
("לצפייה בפרויקט", "שליחה") לא תאם את דרישת העיצוב — "חצים ואייקונים שמובילים
לפעולה יופיעו **מימין** לטקסט" — כי סדר ה-DOM (טקסט ואז אייקון) גרם לאייקון
להופיע *משמאל* לטקסט תחת RTL. תוקן בכל 4 מיקומי הכפתורים (כרטיס פרויקט, עמוד
פרויקט בודד, טופס יצירת קשר) על ידי החלפת סדר ה-`<svg>` וה-`<span>`.
